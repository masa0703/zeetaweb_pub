Managing Trees Help

Switch, create, and share trees from the left bar on the edge of the editor. Notifications, settings, and log out are on the right side of the header.

Create a Tree

Select + in the left bar, enter a name and description, and create it. The editor switches to the new tree.

Invite Members

Open the left bar with ☰, choose ⋯ → “Member management” on a tree, then specify an email address and role to send an invitation.

Manage Notifications

Use the notification bell in the header to mark notifications as read. You can also mark them all as read at once.

Workflows by Use Case

1) After You Log In

  1. The editor opens the tree you used last (the first tree in the list the first time)
  2. If you have no trees yet, the editor shows a screen that guides you to create one
  3. Use ⚙ (Settings) in the header to switch the theme and between Japanese and English. Your choice is remembered the next time you open the page in the same browser

2) Managing Trees

  1. Switch: click a round icon (the first letter of a tree name) in the left bar. Hover to see the tree name. Trees are listed with the most recently opened first (your trees and shared trees in one list; shared trees are marked E or V)
  2. Open the list: ☰ at the left of the header opens the named tree list over the page (click outside or press Esc to close). Drag the right edge of the list to change its width (the width is kept for next time)
  3. Create: + in the left bar → enter details → create
  4. Edit name and description: ⋯ on a tree in the list → “Edit tree” → save
  5. Delete: ⋯ on a tree in the list → “Delete” → confirm in the dialog
  6. MCP integration: ⋯ on a tree in the list → “MCP integration” to get the MCP connection URL
  7. Share a tree: ⋯ on a tree in the list → “Member management” → invite or remove members

3) Managing Members

  1. Invite: enter an email address and role in the member management dialog, then send
  2. Cancel invitation: click × in the pending invitations list
  3. Remove member: click × in the member list (Owner only)

4) Notifications

  1. Click a notification to mark it as read and, when applicable, open its linked page
  2. Use “Mark all as read” to mark every notification as read

5) Member Roles (Permissions)

Assign a role when inviting a member. Owners can change roles later.

Node Editing Help

The node editor is primarily used for editing, restructuring, searching and sorting, and managing the trash.

Edit and Save

Edit the title and content, then save with the Save button or Cmd/Ctrl + Enter. The author, creation date, update date, and last updater appear in the node details dialog; the author cannot be changed on this screen.

Change the Structure

Update the tree structure by creating child or sibling nodes, duplicating nodes, adding parents, or moving nodes to a new parent. DAG structures with multiple parents are supported.

Manage the Trash

Deleting normally moves a node to the trash. For a node with multiple parents, choose whether to unlink it from the visible parent or move it to the trash. The trash view lets you restore or permanently delete nodes.

Screen Images

The numbers correspond to the explanations that follow. The screenshots show the English UI. On small screens, the images scroll horizontally.

Workflows by Use Case

1) Editing and Saving

  1. Select a node and edit its title and content. The author, creation date, update date, and last updater are shown in 4 Node details
  2. Click 5 Save, or press Cmd/Ctrl + Enter
  3. If you select another node with unsaved changes, a confirmation dialog appears
  4. Your scroll position is preserved when returning from preview to edit view

2) Changing the Node Structure

  1. Create child node: Alt+N (adds a child to the selected node)
  2. Create sibling node: Alt+Shift+N (adds a node under the same parent)
  3. Duplicate node: Alt+M (duplicates it under the parent in the currently displayed path)
  4. Add parent: Cmd/Ctrl+C → select the node to use as a parent → Cmd/Ctrl+V
    → The node becomes part of a DAG structure with multiple parents
  5. Move to a new parent: Cmd/Ctrl+X → select the new parent node → Cmd/Ctrl+V
    → The node is detached from its original parent and moved under the new one

3) Searching for Nodes

Keyword search and semantic search using the vector database run in parallel. Nodes found by vector search are labeled “Vhit.”

  1. Open the search popup with 2 Node search or Alt+F, then enter keywords in 9 Keyword input
  2. Enter multiple space-separated keywords to perform an AND search
  3. Enter id: followed by a node’s public ID to find that node directly (6 alphanumeric characters; for example, id:LHuB38)
  4. Switch 10 Search scope between root (the entire tree) and selected (the selected node and its descendants)
    → The scope applies to keyword search. Vhit results (AI-related suggestions) are drawn from all content you can access
  5. Switch between AND and OR modes in the popup (default: AND)
  6. To search titles only, enable 11 only title. Content is excluded from the search, and the AI-related search (Vhit) is not performed either
  7. Search combines keyword and AI vector search. When relevant results exist, AI-related nodes appear below the “— Vhit —” divider
  8. Click the “Vhit xx results” link to scroll to the “— Vhit —” divider (hover text: “vector search”)
  9. Click a matched node to keep it selected with a blue outline, then use ‹ X/Y › on the right to move between matches (the current match uses a distinct highlight)
  10. The search popup stays open after you pick a result, so you can compare it with the content. Close it with the popup’s × or Esc

4) Sorting Nodes

  1. Open “Sort” from the parent node’s vertical three-dot menu to set the order of its child nodes
  2. Combine manual / created date / updated date / title with ascending or descending order. The setting is saved per node
  3. Top-level nodes are configured with “root sort” in the “Normal ▼” menu
  4. In manual sort mode only, move the selected node with Alt+↑ / Alt+↓

5) Deleting and Restoring

  1. Delete: select “Trash” or press Delete / Backspace
  2. A node with one parent is moved to the trash after confirmation
  3. For a node with multiple parents, radio buttons let you choose between unlinking it from the parent visible in the tree and moving the node to the trash
  4. Open the trash view with the “Trash” button in the toolbar
  5. Restore: select “Restore” in the trash view
  6. Permanent deletion: select “Delete permanently” in the trash view
  7. Creating, duplicating, and moving nodes are disabled in the trash view. Only “Restore” and “Delete permanently” are available.

6) Working with Images

  1. Add an image: drag and drop an image file into the content area or paste it from the clipboard (it is inserted at the cursor)
  2. Image menu: click the image icon above the content area to open the menu
  3. Choose “Open in new tab” or “Delete” from the menu. The filename and thumbnail also appear in the menu
  4. Images cannot be added in preview-only mode (a notice is displayed)
  5. Supported formats: JPEG / PNG / GIF / WebP / SVG　　Maximum file size: 5MB

7) Managing Parent Relationships

  1. Open 3 Parent nodes to check parent node names and relationship types
  2. Remove a parent: when the node has multiple parents, select × in the dropdown to unlink that parent. The last remaining parent cannot be removed. Use “move to a new parent” to move the node, and “Trash” to delete it
  3. Change relationship type: choose one of the following from the parent node dropdown
    • STRUCTURAL: Standard parent-child structure (default)
    • REFERENCE: Reference relationship (a weaker association)

8) Node History Navigation

  1. Back: Alt + ← or the ← button in 1 Reference history
  2. Forward: Alt + → or the → button in 1 Reference history
  3. This navigates the history of selected nodes, not the browser history
  4. This is different from restoring content to a past state. For content restore, see “14) Viewing Node Update History and Restoring Past States”

9) Display Settings

  1. Markdown preview: toggle the “markdown preview” checkbox in the toolbar ON or OFF
  2. While previewing, press e to return to edit view
  3. View as HTML: when content begins with <!DOCTYPE html or <html, the “Open as HTML in new tab” button in the CONTENT header is enabled (DOCTYPE is case-insensitive, and an opening ``` followed by a newline is allowed; otherwise the button is disabled and dimmed)
  4. 7 Editor toolbar switches between write only, preview only, full screen, and other modes
  5. Reverse tree: switch to the “Reverse tree” tab in the toolbar
    → Displays reverse paths from the selected node toward the root as a tree
  6. Reload tree: Alt + R
  7. Expand all child nodes: Alt + O
  8. Collapse all child nodes: Alt + L

10) Working with Root Nodes

  1. Use the “Normal ▼” menu to create top-level nodes, collapse child nodes, and configure root sort
  2. You cannot move a node directly under the root by unlinking its last parent relationship

11) Editing Tables

  1. In edit mode with the cursor inside a table, click the table button in 7 Editor toolbar to open the popup table editor loaded with that table
  2. To create a new table, place the cursor outside any table in edit mode, then click the table button
  3. You can add or remove rows and columns, select and copy cells, and paste from Excel or a spreadsheet
  4. When multiple cells are selected, the footer shows the sum of their numeric values (for values such as “¥1,850,000,” “1980 yen,” and “20%,” the numeric portion of each cell is extracted and totaled; cells without numbers are ignored)

12) Searching Within the Content

  1. Type into 6 In-content search on the CONTENT row, then press Enter or the magnifier
  2. Matches within the displayed node’s content are highlighted. Use the previous/next arrows to move between matches
  3. Clearing the search box removes the highlights. To look for another node, use the search in 3)

13) Viewing the Author, Creation Date, Update Date, and Last Updater

  1. Select a node and click 4 Node details (the i in a circle) at the top right
  2. 12 Author, creation date, update date, and last updater at the top of the dialog shows the author, creation date, update date, and last updater. The last updater is the user who made the most recent update; updates made via MCP include the client name. If unknown, (none) is shown. This dialog is for viewing the information only

14) Viewing Node Update History and Restoring Past States

  1. Open 4 Node details to see 13 Content history list with the newest entries first. The most recent version is selected initially
  2. Each timestamp in the list is when that content was written. Every row shows who wrote that content and when (the current row shows the last update time). You can also see who made the update; updates made via MCP include the client name
  3. Select a row in the list to show 14 Past content. After checking the content, click 15 Restore and confirm to restore it
  4. The radio button on the left of each history row is used to compare versions. It is not selected initially. Hovering over it shows "Select the version to compare with"
  5. Pick a comparison target with the radio button and click Compare to see the differences between the selected row and that version. Added lines are shown in green and removed lines in red. The comparison always runs from the older version to the newer one, and it is also available to Viewers
  6. 15 Restore applies to the row you click and select. It is not related to the radio selection
  7. Restore applies to the content only. It does not roll back the title or parent relationships. The content from before the restore also stays in the history
  8. Content history keeps up to the latest 100 entries per node. Nothing is deleted after 7 days. Updates that do not change the content add no history
  9. A node with no history cannot be restored. Viewers can browse the history, but the Restore button is not shown
  10. If the node was updated elsewhere, the latest content and history are reloaded. Check the content again before restoring

15) Opening Mermaid Diagrams in a New Tab and Zooming

  1. Switch the content to preview and click a displayed Mermaid diagram
  2. The selected diagram opens in a new tab. You can zoom in and out, fit it to the window, zoom with the mouse wheel, and pan by dragging
  3. This works on Mermaid diagrams. To open HTML content in a new tab, use 8 View as HTML

MCP / API Integration Help

Zeeta Web supports the official OAuth authorization flow for MCP (Model Context Protocol). Simply register the tree-specific MCP connection URL with your MCP client, then complete authorization by signing in to Zeeta and granting access in your browser. You do not need to store secrets in a configuration file (JSON / TOML).

Register the URL

Use on the tree card in My Page to copy that tree’s MCP connection URL, then register it with your MCP client.

Grant Access in Your Browser

When the client requests a login, the Zeeta consent screen opens in your browser. Check the target tree and permissions, then select “Allow.”

Start Using It

After connecting, access tokens refresh automatically, so there is no key to replace. You can search, create, and update nodes using natural language.

Get an MCP Connection URL

  1. Open My Page and click (MCP integration) on the target tree’s card
  2. Under “MCP connection URL (for this tree),” select “Copy URL”
  3. Register the copied URL with your MCP client (see the client-specific instructions below)

The URL follows the format https://<your-domain>/api/mcp/trees/<number>, and the complete URL is displayed on screen. You do not need to construct the tree ID yourself.

This button is visible to the tree owner. If you participate as an Editor or Viewer, ask the owner to share the URL with you. The URL is not a secret, but only members of that tree can connect.

Connect from Codex

Codex CLI

codex mcp add zeeta --url https://<your-domain>/api/mcp/trees/<number> codex mcp login zeeta

codex mcp login opens your browser and displays the Zeeta consent screen. Grant access to complete the connection. Use codex mcp list to check status and codex mcp logout zeeta to disconnect. OAuth login is available only for Streamable HTTP servers (Zeeta’s MCP connection URL uses Streamable HTTP).

Codex Desktop App / IDE Extension

  1. Desktop app: open Settings → MCP servers → Add server (in the IDE extension, open the gear menu → MCP servers → Add server)
  2. Change “Type” to Streamable HTTP

    The default is STDIO. With STDIO selected, the input is a launch command for a local process, so entering a URL there will not connect. Changing the type switches the field to a URL input.

  3. Enter a name (for example, zeeta) and the MCP connection URL, save, and restart the app or extension (arguments and environment variables can remain empty)
  4. Select the “Authenticate” button in the MCP server list

    The Zeeta consent screen opens in your browser. Select “Allow.” The button indicates that the server has not yet been authenticated.

The tool list is not loaded until authentication is complete. If you mention the server in chat before authenticating, the response may say that the MCP server is unknown. Authenticate first.
Codex CLI, the IDE extension, and the desktop app on the same machine share MCP settings from config.toml. Adding a server in one makes it available to the others.

Connect from Claude

Claude Code (CLI / Desktop App)

claude mcp add --transport http zeeta https://<your-domain>/api/mcp/trees/<number>

After adding the server, run /mcp in a Claude Code session, select zeeta, and choose Authenticate. The Zeeta consent screen opens in your browser; grant access to connect. Use claude mcp list to check the connection state (✔ Connected / ! Needs authentication). Non-interactive execution (claude -p) cannot open the authorization flow, so authenticate in advance using /mcp in an interactive session or claude mcp login zeeta. Do not specify --header "Authorization: Bearer ..." for OAuth, because doing so uses that header instead of OAuth.

Claude Desktop / claude.ai (Custom Connector)

  1. Individual plan: open Customize → Connectors (for Team / Enterprise, the owner opens Organization settings → Connectors)
  2. Select the add button → choose Web under “Custom” → paste the MCP connection URL
  3. After saving, complete the requested OAuth authorization on the Zeeta consent screen

Custom connectors connect from Anthropic’s cloud, so you need a production HTTPS URL reachable from the internet. A local development URL using localhost cannot be registered (it can be used for local connections from Codex CLI or Claude Code).

Permissions (Scopes)

Only members of the tree identified by the URL can connect through OAuth. The granted permissions always reflect your current role in that tree.

Tree Role Granted Scopes Capabilities
Owner / Editor mcp:read mcp:write Read + create, update, link, and move to trash
Viewer mcp:read Read only (write tools are rejected with insufficient_scope)
  • A token is bound to one tree (URL) and cannot be used with another tree’s URL.
  • If your role changes from Editor to Viewer, existing tokens immediately lose write access.
  • If you are removed from the tree, existing tokens become invalid immediately (reauthorizing will not restore access to that tree).
  • Access tokens are short-lived (one hour); the client renews them automatically with a refresh token.

Disconnecting and Reauthorizing

  • Codex CLI: disconnect with codex mcp logout zeeta, then reauthorize with codex mcp login zeeta.
  • Claude Code: open /mcp and choose Re-authenticate from the target server’s menu.
  • claude.ai connector: remove and reconnect the connector in Connectors settings.
  • To revoke a token on the server, remove that user from the tree; the token becomes invalid immediately.

Troubleshooting

  • The chat says it does not recognize or know about the MCP server

    The server has not been authenticated yet. Its tool list is not loaded until authentication is complete. In Codex Desktop or the IDE extension, select Authenticate in the MCP server list. For Codex CLI, run codex mcp login <name>. For Claude Code, run /mcp and choose Authenticate.

  • I entered the URL, but Codex Desktop or the IDE extension cannot connect

    If “Type” is still set to STDIO, the input is treated as a launch command and the client tries to run the URL as a local process. Switch to Streamable HTTP, then paste the URL again.

  • I keep being asked to authenticate, or the status remains Needs authentication

    Make sure the URL is correct and includes /api/mcp/trees/<number>. There is no /api/mcp endpoint without a tree number.

  • The consent screen says that you are not a member of this tree

    The account currently signed in to Zeeta is not a member of that tree. Ask the owner to invite you, or sign in again with a different account.

  • A write tool fails with insufficient_scope

    Your role in the tree is Viewer. Ask the owner to change it to Editor or Owner, then reauthorize in the client.

  • An invalid_target or redirect_uri error appears immediately after connecting

    This occurs when the domain in the URL differs from the domain you are actually connecting to. Copy the URL again from My Page and register that URL.

  • Invalid state parameter appears during authentication in a development environment

    This occurs when 127.0.0.1 and localhost are mixed in local development. Browsers treat them as separate hosts, so the cookie set when login begins is not sent to the callback. Open My Page using localhost, then register the URL copied from there. This does not occur in production, which uses a single domain.

  • The claude.ai connector cannot connect

    You need an HTTPS URL that Anthropic’s cloud can reach. URLs restricted to an internal network and localhost URLs cannot be used.

Key MCP Commands

  • Read get_root_node_id

    Returns the tree’s root node ID.

  • Read read_node

    Returns the specified node’s title, content, parent-child relationships, child sorting settings, and other details. Set include_images to also retrieve image metadata.

  • Read get_children

    Returns detailed information for all children of the specified node, including content and child sorting settings. Set include_images to also retrieve image metadata.

  • Read get_parents

    Returns detailed information for all parents of the specified node, including content and child sorting settings.

  • Read read_node_image

    Returns one node image at a time as base64.

  • Read search_nodes

    Performs node search by keyword. Node IDs are 6-character public IDs. With only_title: true, only titles are searched and vector search is skipped. By default it runs keyword and vector search, returning word[] for keyword matches, vector[] for AI-related candidates not duplicated in the keyword results, a combined items[] list, and the counts word_count / vector_count.

  • Write create_node

    Creates a new node. Child sorting settings can also be specified.

  • Write create_node_image

    Adds a base64 image to a node and returns an image URL for insertion into the node content.

  • Write create_node_tree

    Creates multiple nodes as a tree structure in one operation.

  • Write update_node

    Updates a node’s title, content, and child sorting settings.

  • Write append_node_content

    Appends text to the end of a node’s content.

  • Write trash_node

    Moves a node to the trash (soft delete).

  • Write link_node / link_nodes

    Adds parent-child relationships between nodes; multiple relationships can be specified at once.

  • Write unlink_node / unlink_nodes

    Removes parent-child relationships between nodes; multiple relationships can be specified at once.

  • Write update_link_relation_type

    Changes the parent-child relationship type (STRUCTURAL / REFERENCE).
