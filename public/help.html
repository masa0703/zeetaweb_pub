English

ツリーの管理ヘルプ

ツリーの切り替え・作成・共有は、編集画面の左端にある左バーで行います。通知・設定・ログアウトはヘッダーの右側にあります。

ツリーを作る

左バーの ＋ から名前と説明を入力して作成します。作成すると、そのツリーの編集画面に切り替わります。

メンバーを招待する

左バーを ☰ で開き、ツリーの ⋯ →「メンバー管理」からメールアドレスと役割を指定して招待します。

通知を処理する

ヘッダーの通知ベルから通知を既読化できます。「すべて既読」で一括既読も可能です。

ユースケース別の流れ

1) ログイン後の表示

  1. ログインすると、最後に開いたツリーの編集画面が開きます（初めてのときは一覧の先頭のツリー）
  2. ツリーが1つも無いときは「新しいツリーを作成」を案内する画面になります
  3. ヘッダーの ⚙（設定）でテーマと日本語／英語を切り替えられます。選択は同じブラウザでの次回表示にも使われます

2) ツリー管理

  1. 切り替え: 左バーの丸アイコン（ツリー名の頭文字）をクリック。マウスを重ねるとツリー名が出ます。ツリーは最後に開いた順に並びます（自分のツリーと共有されたツリーを区別せず1列。共有されたツリーには E／V の印が付きます）
  2. 一覧を開く: ヘッダー左端の ☰ で、ツリー名つきの一覧を画面に重ねて開きます（外側をクリックするか Esc で閉じる）。一覧の右端をドラッグすると幅を変えられます（次回も同じ幅で開きます）
  3. 作成: 左バーの ＋ → 入力 → 作成
  4. 名前・説明の変更: 一覧でツリーの ⋯ →「ツリーを編集」→ 保存
  5. 削除: 一覧でツリーの ⋯ →「削除」→ 確認ダイアログで確定
  6. MCP連携: 一覧でツリーの ⋯ →「MCP連携」からMCP接続URLを取得
  7. ツリーの共有: 一覧でツリーの ⋯ →「メンバー管理」→ 共有したいメンバーを招待・削除

3) メンバー管理

  1. 招待: メンバー管理モーダルでメールアドレスと役割を入力して送信
  2. 招待取り消し: 招待中リストの × をクリックして取り消し
  3. メンバー削除: メンバー一覧の × をクリックして削除（Ownerのみ）

4) 通知

  1. 通知アイテムをクリックすると既読になり、必要に応じてリンク先へ遷移
  2. 「すべて既読」で通知を一括既読化

5) メンバー役割（権限）

メンバーには招待時に役割を設定します。後から変更することも可能です（Ownerのみ）。

役割 ノード作成・編集 ノード削除・移動 メンバー管理 ツリー削除
Owner ○ ○ ○ ○
Editor ○ ○ × ×
Viewer × × × ×

Viewer はノードの閲覧・検索のみ行えます。

プライバシーポリシー

最終更新日: 2026-11-08

zeetaweb（以下「本サービス」）が扱う情報と、その使い道を説明します。

集める情報

  • GoogleまたはGitHubでログインすると、アカウントを識別するための各サービスのユーザーID、メールアドレス、表示名、プロフィール画像のURLを受け取ります。GitHubでは、公開メールアドレスが取得できない場合、プライマリメールアドレスを受け取ります。
  • あなたが作成したツリー・ノードの内容と、添付した画像
  • 不正利用の調査や障害対応のため、一部の操作について、日時、ユーザー、操作の種類と対象、IPアドレス、ブラウザの種類（User-Agent）などを記録することがあります。
  • ログイン状態の維持や認証の安全確認のためのCookie。また、表示設定や編集中の下書きなどを、お使いのブラウザの保存領域に保存することがあります。

使い道

受け取った情報は、ログイン、プロフィールの表示、ツリーの保存・表示・検索・共有、招待先の照合と招待メールの送信、不正利用の調査、障害対応に使います。広告には使わず、第三者に販売しません。

外部サービス

本サービスは次の外部サービスを使っており、必要な範囲で情報がそれらのサービスで処理されます。

  • Cloudflare: サーバー、データベース、画像の保存
  • Cloudflare Workers AI と Vectorize: 関連するノードを検索するため、ノードのタイトル、親ノードのタイトルを含むパス、本文、および検索語をWorkers AIでベクトルに変換し、検索用のベクトルをVectorizeに保存します。
  • Mailgun: 招待メールの送信。招待先のメールアドレス、招待者の表示名またはメールアドレス、ツリー名、付与する権限、招待URLと有効期限がMailgunで処理されます。
  • Google / GitHub: ログイン
  • 画面表示に必要なライブラリなどの配信に、jsDelivrやCloudflareなどのCDNを使うことがあります。その際、ブラウザから各CDNに接続されます。

共有とMCP連携

招待したメンバーは、付与された権限に応じてツリーを閲覧・編集できます。招待メールには招待者の表示名などが含まれます。MCPクライアントを連携した場合は、許可した範囲のツリー情報をそのクライアントが取得・操作できます。連携先での情報の扱いは、その提供者の条件と設定をご確認ください。

安全管理

情報へのアクセスを権限に応じて制限し、認証用のCookieには安全性を高める設定を使っています。ただし、情報の完全な安全性を保証することはできません。

変更

このポリシーは、本サービスや情報の扱いの変更に応じて更新します。Googleユーザーデータの使い方を変える場合は、本サービス内などでお知らせします。

ノード編集ヘルプ

ノード編集は「編集」「構造変更」「検索/並び替え」「ゴミ箱操作」を中心に使います。

編集して保存

タイトル・本文を編集し、保存ボタンまたは Cmd/Ctrl + Enter で確定します。作成者・作成日・更新日・更新者はノード詳細ダイアログに表示され、画面上では作成者を変更できません。

構造を操作

子/兄弟ノード作成、複製、親追加・親移動でツリー構造を更新できます。複数の親を持てる DAG 構造に対応しています。

ゴミ箱を操作

削除は通常はゴミ箱へ移動です。複数親ノードでは、今見えている親との関係解消かゴミ箱移動かを選べます。ゴミ箱ビューで復元や完全削除ができます。

画面イメージ

番号は後続の説明文と対応しています。画像は日本語表示のサンプルです。小さい画面では画像を横にスクロールできます。

ユースケース別の流れ

1) 編集・保存

  1. ノードを選択し、タイトル・本文を編集します。作成者・作成日・更新日・更新者は 4 ノード詳細 で確認できます
  2. 5 保存 をクリック、または Cmd/Ctrl + Enter
  3. 別ノードを選択すると未保存の変更がある場合に確認ダイアログが表示されます
  4. プレビュー表示から編集表示に戻すときは、スクロール位置が引き継がれます

2) ノード構造の操作

  1. 子ノード作成: Alt+N（選択ノードの子として追加）
  2. 兄弟ノード作成: Alt+Shift+N（同じ親の下に追加）
  3. ノード複製: Alt+M（現在表示しているパスの親ノード下に複製）
  4. 親追加: Cmd/Ctrl+C → 親にしたいノードを選択 → Cmd/Ctrl+V
    → ノードが複数の親を持つ DAG 構造になります
  5. 親移動: Cmd/Ctrl+X → 新しい親ノードを選択 → Cmd/Ctrl+V
    → 元の親から切り離して別の親へ移動します

3) ノードを検索する

ワード検索と、ベクトルDBによる意味検索を並行して実施します。ベクトルDBによる検索でヒットしたノードは「Vhit」と表現します。

  1. 2 検索ボタン、または Alt+F で検索ポップアップを開き、9 検索欄 にキーワードを入力して検索します
  2. スペース区切りで複数キーワードを入力するとAND検索になります
  3. id:公開ID と入力すると特定のノードを直接検索できます（6文字の英数字。例: id:LHuB38）
  4. 10 検索範囲 を root（ツリー全体）または selected（選択ノード以下）で切り替えられます
    → scope が適用されるのはワード検索です。Vhit（AI 関連候補）はアクセス可能な範囲から提案されます
  5. AND / OR モードをポップアップで切り替えられます（デフォルト: AND）
  6. タイトルを検索する: 11 only title にチェックを入れて検索します。本文は対象外となり、AI関連検索（Vhit）も行いません
  7. 検索時はワード検索に加えて AI ベクトル検索も併用され、該当があれば「— Vhit —」区切りで AI 関連ノードが表示されます
  8. 「Vhit xx件」のリンクをクリックすると「— Vhit —」区切りまでスクロールします（マウスオーバーで「vector検索」と表示）
  9. ヒットしたノードをクリックすると選択が青枠で保持され、右端の ‹ X/Y › で前後のマッチへ移動できます（現在のマッチは別色で強調）
  10. 検索結果を選んだ後も検索窓は残るため、本文と見比べられます。閉じるときは検索窓の × または Esc を使います

4) ノードを並び替える

  1. 親ノードの縦三点メニューから「ソート」を開くと、その子ノードの並び順を設定できます
  2. 手動 / 作成日 / 更新日 / タイトル と、昇順 / 降順を組み合わせます。設定はノードごとに保存されます
  3. 最上位のノードは「通常▼」メニューの「rootのソート」で設定します
  4. 手動ソート時のみ Alt+↑ / Alt+↓ で選択ノードの順番を移動できます

5) 削除・復元

  1. 削除: 「ゴミ箱」または Delete / Backspace
  2. 単一親ノードでは確認後にゴミ箱へ移動します
  3. 複数親ノードでは、ツリー上で見えている親との関係を解消するか、このノードをゴミ箱へ移動するかをラジオボタンで選べます
  4. ゴミ箱ビューへの切り替え: ツールバーの「ゴミ箱」ボタン
  5. 復元: ゴミ箱ビューで「戻す」
  6. 完全削除: ゴミ箱ビューで「完全に削除」
  7. ゴミ箱ビュー表示中はノードの作成・複製・移動は無効です。「戻す」「完全に削除」のみ操作できます。

6) 画像の操作

  1. 画像を追加: 画像ファイルを内容エリアへドラッグ&ドロップ、またはクリップボードから貼り付け（カーソル位置に挿入されます）
  2. 画像メニュー: 内容上部の画像アイコンをクリックするとメニューが開きます
  3. メニューから「別タブで表示」「削除」を選べます。ファイル名とサムネイルもメニュー内で確認できます
  4. プレビューのみ表示中は画像の追加はできません（案内が表示されます）
  5. 対応形式: JPEG / PNG / GIF / WebP / SVG　　最大ファイルサイズ: 5MB

7) 親ノード関係の操作

  1. 3 親ノード を開き、親ノード名や関係タイプを確認します
  2. 親ノード削除: 親が複数ある場合、ドロップダウンの × からその親との関係を解除できます。最後の1つの親は解除できません。移動には「親移動」、削除には「ゴミ箱」を使います
  3. 関係タイプ変更: 親ノードドロップダウンで以下から選択
    • STRUCTURAL: 標準的な親子構造（デフォルト）
    • REFERENCE: 参照関係（弱い結びつき）

8) ノード参照履歴ナビゲーション

  1. 戻る: Alt + ← または 1 参照履歴 の ← ボタン
  2. 進む: Alt + → または 1 参照履歴 の → ボタン
  3. ブラウザの「戻る」ではなく、選択したノードの履歴を辿ります
  4. 本文を過去の状態に戻す操作とは異なります。本文の復元は「ノード更新履歴を見る・過去の状態に戻す」を参照してください

9) 表示設定

  1. Markdown プレビュー: ツールバーの「markdown preview」チェックボックスで ON/OFF 切り替え
  2. プレビュー表示中は e キーで編集表示へ戻れます
  3. HTMLとして表示: 内容が <!DOCTYPE html または <html で始まる場合、CONTENT ヘッダーの「HTMLとして別タブで開く」ボタンが有効になります（DOCTYPE の大文字小文字差と先頭の ``` + 改行は許容。それ以外は無効・淡色表示）
  4. 7 エディタのツールバー で編集のみ・プレビューのみ・全画面などを切り替えられます
  5. リバーストリー（逆ツリー）: ツールバーの「逆ツリー」タブで切り替え
    → 選択ノードからルートに向かう逆方向のパスをツリー形式で表示します
  6. ツリー再読み込み: Alt + R
  7. 子ノード全展開: Alt + O
  8. 子ノード全折りたたみ: Alt + L

10) 最上位（ルート直下）の操作

  1. 「通常▼」メニューから最上位ノードの新規作成、子ノードの折りたたみ、rootのソートができます
  2. 最後の親との関係を解除してルート直下に移すことはできません

11) 表（テーブル）の編集

  1. 編集モードでカーソルが表内にある状態で、7 ツールバー のテーブルボタンをクリックすると、既存の表を読み込んだポップアップ式テーブルエディタが開きます
  2. 新しい表を作る場合は、編集モードで表の外にカーソルを置いてからテーブルボタンをクリックします
  3. 行・列の追加／削除、セルの選択・コピー、Excel やスプレッドシートからの貼り付けに対応しています
  4. 複数セルを選択すると、フッターに数値の合計が表示されます（「¥1,850,000」「1980円」「20%」など、各セルから数値部分を抽出して合算。数字を含まないセルは無視）

12) 表示中の本文を検索する

  1. CONTENT 行の 6 本文内検索 に文字を入力し、Enter または虫眼鏡を押します
  2. 表示中ノードの本文内で一致した箇所が強調されます。前後の矢印で一致箇所へ移動できます
  3. 検索欄を空にすると強調表示を解除します。別のノードを探す場合は 2 の検索を使います

13) 作成者・作成日・最終更新日・更新者を見る

  1. ノードを選択し、右上の 4 ノード詳細（丸の中に i） をクリックします
  2. ダイアログ上部の 12 作成者・作成日・更新日・更新者 に作成者・作成日・更新日・更新者が表示されます。更新者は最終更新した人で、MCP経由の更新ではクライアント名も併記されます。入っていない場合は (none) と表示されます。ここでは情報の確認のみ行えます

14) ノード更新履歴を見る・過去の状態に戻す

  1. 4 ノード詳細を開くと、13 本文の履歴一覧 が新しい順に表示されます。最初は直前の版が選択されています
  2. 一覧の日時は、その内容が「更新された日時」です。どの行も、その内容を書いた人と日時が表示されます（現在行は最終更新日時）。更新者も確認でき、MCP経由の更新ではクライアント名も併記されます
  3. 履歴の行を選ぶと、14 過去の本文 が表示されます。内容を確かめてから 15 戻す を押し、確認に同意すると復元されます
  4. 履歴一覧の各行の左にあるラジオボタンは履歴の比較に使います。初期状態では選択されていません。マウスを乗せると「比較対象を選択してください」と表示されます
  5. ラジオで比較相手を選び「比較」を押すと、選択中の行と比較相手の差分が表示されます。追加された行は緑、削除された行は赤です。表示の向きは常に古い版→新しい版で、Viewer でも使えます
  6. 15 戻す の対象は、クリックして選択した行です。ラジオの選択とは関係ありません
  7. 復元の対象は本文です。タイトルや親子関係を巻き戻す操作ではありません。復元前の本文も履歴に残ります
  8. 本文の履歴はノードごとに最新100件まで保持します。7日経過による削除はありません。本文が変わっていない更新は履歴を増やしません
  9. 履歴がないときは復元できません。Viewer は履歴を閲覧できますが「戻す」は表示されません
  10. 他の場所で更新されていた場合は、最新の本文と履歴を読み直します。内容を確認し直してから復元してください

15) Mermaid図を別タブで表示・拡大する

  1. 本文をプレビュー表示にし、表示されたMermaid図をクリックします
  2. 選んだ図が別タブで開きます。拡大・縮小・全体表示、ホイールによるズーム、ドラッグによる移動ができます
  3. この操作の対象はMermaid図です。HTML本文の別タブ表示は 8 HTML表示 を使います

MCP / API 連携ヘルプ

Zeeta Web は MCP（Model Context Protocol）の公式 OAuth 認証に対応しています。 MCPクライアントには ツリーごとの MCP接続URL を登録するだけで、認証はブラウザ上でZeetaにログイン・許可して完了します。 設定ファイル（JSON / TOML）に秘密情報を書き込む必要はありません。

URLを登録する

マイページのツリーカードにある から、そのツリー専用の MCP接続URL をコピーしてMCPクライアントに登録します。

ブラウザで許可する

クライアントがログインを要求すると、ブラウザでZeetaの同意画面が開きます。対象ツリーと権限を確認して「許可する」を押します。

そのまま使う

接続後はアクセストークンが自動更新されるため、キーの貼り替えは不要です。自然言語でノードを検索・作成・更新できます。

MCP接続URL を取得する

  1. マイページを開き、対象ツリーのカードにある （MCP連携）をクリックします
  2. 表示された「MCP接続URL（このツリー専用）」の「URLをコピー」を押します
  3. コピーしたURLをMCPクライアントへ登録します（下記の各クライアント手順を参照）

URLは https://<your-domain>/api/mcp/trees/<番号> の形式で、画面には完成形が表示されます。 ツリーIDを自分で組み立てる必要はありません。

このボタンはツリーのオーナーに表示されます。編集者・閲覧者としてツリーに参加している場合は、オーナーからURLを共有してもらってください。 URLは秘密情報ではありませんが、接続できるのはそのツリーのメンバーだけです。

Codex から接続する

Codex CLI

codex mcp add zeeta --url https://<your-domain>/api/mcp/trees/<番号> codex mcp login zeeta

codex mcp login でブラウザが開き、Zeetaの同意画面が表示されます。許可すると接続が完了します。 状態は codex mcp list、切断は codex mcp logout zeeta で確認・実行できます。 OAuthログインは Streamable HTTP サーバーでのみ利用できます（ZeetaのMCP接続URLは Streamable HTTP です）。

Codex デスクトップアプリ / IDE拡張

  1. デスクトップアプリ: 設定（Settings）→ MCP servers → Add server を開きます（IDE拡張は歯車メニュー → MCP servers → Add server）
  2. 「タイプ」を ストリーミング可能な HTTP（Streamable HTTP） に切り替えます

    初期状態は STDIO です。STDIOのままだと入力欄が「起動用コマンド」（ローカルプロセスの起動コマンド）なので、そこにURLを入れても接続できません。タイプを切り替えるとURL入力欄に変わります。

  3. 名前（例: zeeta）と MCP接続URL を入力して保存し、アプリ／拡張を再起動します（引数・環境変数は空のままでよい）
  4. MCPサーバー一覧に表示される「認証する」ボタンを押します

    ブラウザでZeetaの同意画面が開くので「許可する」を押します。ボタンが出ているのは未認証の状態です。

認証を完了するまでツール一覧は読み込まれません。そのため未認証のままチャットでサーバー名を指定しても「そのMCPは不明」という応答になります。先に「認証する」を済ませてください。
同一マシンの Codex CLI / IDE拡張 / デスクトップアプリは config.toml のMCP設定を共有します。片方で追加すれば他方にも反映されます。

Claude から接続する

Claude Code（CLI / デスクトップアプリ）

claude mcp add --transport http zeeta https://<your-domain>/api/mcp/trees/<番号>

追加後、Claude Code のセッション内で /mcp を実行し、zeeta を選んで認証（Authenticate）を実行します。 ブラウザでZeetaの同意画面が開き、許可すると接続されます。claude mcp list で接続状態（✔ Connected / ! Needs authentication）を確認できます。 非対話実行（claude -p）では認証フローを開けないため、事前に対話セッションの /mcp または claude mcp login zeeta で認証しておきます。 --header "Authorization: Bearer ..." を指定するとOAuthではなくそのヘッダーが使われるため、OAuth方式では指定しません。

Claude デスクトップ / claude.ai（カスタムコネクタ）

  1. 個人プラン: Customize → Connectors（Team / Enterprise はオーナーが Organization settings → Connectors）を開きます
  2. 追加ボタン →「Custom」の Web を選び、MCP接続URL を貼り付けます
  3. 保存後にOAuth認証を求められるので、Zeetaの同意画面で許可します

カスタムコネクタはAnthropicのクラウドから接続されるため、インターネットから到達できる本番URL（HTTPS）が必要です。 localhost の開発環境URLは登録できません（Codex CLI / Claude Code のローカル接続では利用できます）。

権限（スコープ）

OAuthで接続できるのは URLが指すツリーのメンバーだけです。付与される権限は、常にそのツリーでのあなたの現在の権限に従います。

ツリーでの権限 付与されるスコープ できること
オーナー / 編集者 mcp:read mcp:write 読み取り + 作成・更新・リンク・ゴミ箱移動
閲覧者 mcp:read 読み取りのみ（書込ツールは insufficient_scope で拒否）
  • トークンは1ツリー（URL）に束縛されます。別ツリーのURLには使えません。
  • 権限が編集者から閲覧者へ変更されると、既存トークンでも書込は即時できなくなります。
  • ツリーのメンバーから外れると、既存トークンは即時無効になります（再認証してもツリーには接続できません）。
  • アクセストークンは短命（1時間）で、クライアントがリフレッシュトークンで自動更新します。

切断・再認証

  • Codex CLI: codex mcp logout zeeta で切断し、codex mcp login zeeta で再認証します。
  • Claude Code: /mcp から対象サーバーのメニューで再認証（Re-authenticate）を選びます。
  • claude.ai コネクタ: Connectors 設定から対象コネクタを削除・再接続します。
  • サーバー側でトークンを失効させたい場合は、そのユーザーをツリーのメンバーから外します（トークンは即時無効になります）。

トラブルシューティング

  • チャットで「そのMCPは不明」「そんなMCPは知らない」と言われる

    まだ認証していない状態です。認証が完了するまでツール一覧は読み込まれません。Codexデスクトップ／IDE拡張ならMCPサーバー一覧の「認証する」、Codex CLIなら codex mcp login <名前>、Claude Codeなら /mcp の Authenticate を実行してください。

  • URLを入れたのに接続できない（Codexデスクトップ／IDE拡張）

    「タイプ」が STDIO のままだと入力欄は「起動用コマンド」で、URLをローカルプロセスとして起動しようとします。ストリーミング可能な HTTP に切り替えてから貼り直してください。

  • 認証を求められ続ける / Needs authentication のまま

    URLが正しいか（/api/mcp/trees/<番号> まで含んでいるか）を確認してください。ツリー番号のない /api/mcp は存在しません。

  • 同意画面で「あなたはこのツリーのメンバーではありません」と表示される

    Zeetaにログインしているアカウントが、そのツリーのメンバーに含まれていません。オーナーに招待を依頼するか、別アカウントでログインし直してください。

  • 書込ツールが insufficient_scope で失敗する

    ツリーでの権限が閲覧者になっています。オーナーに編集者以上への変更を依頼し、その後クライアント側で再認証してください。

  • 接続直後に invalid_target や redirect_uri のエラーになる

    URLのドメインが実際に接続しているドメインと異なる場合に発生します。マイページからコピーし直したURLで登録してください。

  • 認証中に Invalid state parameter と表示される（開発環境）

    ローカル開発で 127.0.0.1 と localhost が混在すると発生します。ブラウザは両者を別ホストとして扱うため、ログイン開始時のクッキーがコールバックへ送られません。localhost 側でマイページを開き、そこでコピーしたURLを登録し直してください。本番環境（単一ドメイン）では発生しません。

  • claude.ai のコネクタが接続できない

    Anthropicのクラウドから到達できるHTTPSのURLが必要です。社内ネットワーク限定や localhost のURLは利用できません。

主要 MCP コマンド一覧

  • 読取 get_root_node_id

    ツリーのルートノード ID を取得します。

  • 読取 read_node

    指定したノードのタイトル・内容・親子関係・子ソート設定などを取得します。include_images で画像メタデータも取得できます。

  • 読取 get_children

    指定したノードの子ノード一覧を、本文・子ソート設定付きの詳細情報でまとめて取得します。include_images で画像メタデータも取得できます。

  • 読取 get_parents

    指定したノードの親ノード一覧を、本文・子ソート設定付きの詳細情報でまとめて取得します。

  • 読取 read_node_image

    ノード画像を1枚ずつ base64 で取得します。

  • 読取 search_nodes

    キーワードでノードを検索します。ノードIDは6文字の公開IDです。only_title: true ではタイトルのみを検索し、ベクトル検索は行いません。通常はワード検索とベクトル検索を行い、word[]（ワード一致）、vector[]（ワード結果と重複しない AI 関連候補）、統合した items[]、件数 word_count / vector_count を返します。

  • 書込 create_node

    新しいノードを作成します。子ソート設定も指定できます。

  • 書込 create_node_image

    base64 画像をノードへ追加し、本文差し替え用の画像 URL を返します。

  • 書込 create_node_tree

    ツリー構造のノードをまとめて作成します。

  • 書込 update_node

    ノードのタイトル・内容・子ソート設定を更新します。

  • 書込 append_node_content

    ノードの内容末尾にテキストを追記します。

  • 書込 trash_node

    ノードをゴミ箱へ移動します（論理削除）。

  • 書込 link_node / link_nodes

    ノード間に親子関係を追加します（複数まとめて指定可）。

  • 書込 unlink_node / unlink_nodes

    ノード間の親子関係を削除します（複数まとめて指定可）。

  • 書込 update_link_relation_type

    親子関係のタイプ（STRUCTURAL / REFERENCE）を変更します。
