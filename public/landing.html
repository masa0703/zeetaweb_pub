Most tools make you pick one place.

  • A tree wants one folder

    A note that belongs in two places ends up in one of them — or gets copied, and the copies drift apart.

  • Tags lose the structure

    A note can carry many tags, but a tag is a flat bucket. The order and nesting you built are gone.

  • Links lose the hierarchy

    Links connect anything to anything, but there is nothing to browse top-down. You get a web, not an outline.

zeeta keeps the outline and drops the one-parent rule.

  1. 1

    More than one parent

    Any node can sit under several parents — a DAG rather than a strict tree. It is still one node: edit it in one place and it changes everywhere.

  2. 2

    A reverse tree

    Flip the view to see a node's parents, and their parents. “Where did this come from?” takes one click.

  3. 3

    Regroup without losing the original

    Collect nodes under a new viewpoint. The hierarchy they came from stays as it was.

Example: where did this requirement come from?

  1. Take meeting notes as usual. Each requirement goes under the meeting where it came up.
  2. Later, add a “Requirements” node and attach the same requirement nodes to it as a second parent.
  3. Months later someone asks why Req 04 exists. Open its reverse tree: it came from the 10/05 kickoff.

Where it came from

  1. 20+ years ago

    zeeta started as a free desktop app. Teams used it to keep a whole project — minutes, requirements, screens, database tables, tests — in one shared tree.

  2. 2025

    Rebuilt from scratch as a web app, with multiple trees per person and sharing per tree.
